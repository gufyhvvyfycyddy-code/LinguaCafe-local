# ADR-0033：真实浏览器验收采用多通道降级，而非绑定单一工具

> 状态：Accepted
> 日期：2026-07-28
> 决策者：用户
> 适用范围：LinguaCafe 本地开发环境中的可见 UI、Reader、Reviewer、导入导出及移动网页准备验收

> **部分取代：** ADR-0034 §6 明确区分普通通道失败与“明确禁止替代通道”的
> 平台安全拒绝；后者不得按本 ADR 自动降级。ADR-0034 §5、§9 同时取代
> 本 ADR §2.3 中的账号、数据库和页面写入授权。

## 1. 背景

M1 Mobile API Foundation 的代码、自动测试、testing MySQL、HTTP 与数据库兼容回归已经完成，但当前官方 Browser 因 localhost URL 安全策略拒绝访问，流程随后反复要求用户手动打开 `/reviews/senses` 并评分。

这一阻塞不代表 LinguaCafe 页面不可用，也不代表真实浏览器验收本身无法完成。根因是旧规则把一个具体浏览器连接器当成事实上的唯一通道，工具级拒绝被错误升级为产品验收阻塞。

用户明确要求降低这种不必要的工具约束：执行 Agent 可以直接使用其他真实浏览器方式完成本地验收，不应频繁把普通、可回滚的开发环境操作交回用户。

## 2. 决策

### 2.1 验收按结果定义

“真实浏览器验收”成立的条件是：

1. 实际渲染目标 LinguaCafe 页面；
2. 使用真实 DOM 和用户事件完成目标操作；
3. 使用真实认证会话；
4. 能检查 Console、Network 和可观察的数据变化；
5. API、数据库和日志只作为补充证据，不冒充页面操作。

验收不绑定某一个浏览器品牌、连接器或 MCP 工具。

### 2.2 允许的通道降级

执行 Agent 按当前可用性使用：

1. 官方 OpenAI Browser 或 Chrome 插件；
2. Chrome DevTools / MCP；
3. 受控 Playwright；
4. Computer Use 或本机系统浏览器自动化；
5. 项目批准、能够提供真实 DOM 与浏览器证据的其他通道。

某一通道因 localhost 连接、连接器、Cookie context、会话或基础设施等普通故障失败，且 system、developer 或工具没有明确禁止同一结果的替代通道时，可以自动切换下一通道，不需要用户再次批准。全部平台允许的当前通道均实际尝试失败，或出现验证码、双重验证、系统级授权等必须由人完成的步骤时，持续目标按 ADR-0037 先记录 `Acceptance Deferred — Not Complete` 并继续独立切片；只有没有其他可运行切片或最终完成审计必须清零该节点时才请求用户介入。

工具自身不可绕过的平台安全限制；本决定只是允许选择另一个合规工具，不要求欺骗、禁用或规避工具安全机制。

### 2.3 本地验收预授权

在任务范围明确且目标是本地 LinguaCafe 开发环境时，执行 Agent 可以直接：

- 启动或重启任务需要的 Laravel、前端、队列、tokenizer 和浏览器进程；
- 当前任务提供的本地测试账号只有在确认位于专用 testing 数据库且权限不高于
  当前切片所需时才复用；
- 账号不存在时按 ADR-0034 只在专用 testing 数据库创建任务专属、
  最小权限、默认非管理员身份，并通过正常 UI 登录；
- 创建可识别、任务专属的测试数据；
- 在真实页面执行评分、撤回、Marker、Tag、创建临时词义、归档/恢复等任务需要且可回滚的动作；
- 查询 API、数据库和日志确认页面操作产生的真实结果；
- 通过产品撤回/恢复入口收口，或仅清理本轮明确创建的数据。

上述动作不需要逐项再次向用户询问，但只适用于 testing 数据库中的任务
专属数据；普通开发数据库、其他用户数据和管理员权限不在预授权内。不得在
普通开发数据库创建临时账号后直接删号清理。任何页面写入前必须取得绑定
同一监听 host/port 和进程的 server-bound 证据，确认实际 HTTP 进程为
`APP_ENV=testing`、连接该专用 testing 数据库并能读取 testing-only sentinel；
单独 PHPUnit/CLI 健康检查不能证明当前服务器。普通 `php artisan serve` 若
未证明这一点，只能用于只读诊断。

### 2.4 保留的安全边界

本决定不授权：

- 清库、drop、truncate、`migrate:fresh`、`db:wipe`；
- 读取或修改 `.env`、密钥和真实用户凭据；
- 绕过认证、权限或 user/language 隔离；
- 修改其他用户数据；
- 通过 fetch/axios 直接调用写接口后声称完成按钮验收；
- 手工改数据库伪造页面结果；
- 清理既有 `.playwright-cli/` 残渣或任务外文件；
- 将普通开发环境授权扩大为生产环境授权。

## 3. 报告要求

最终报告必须记录：

- 最终使用的浏览器通道；
- 首选通道失败时的错误和降级过程；
- 页面、DOM 操作、登录、Console、Network 和数据 delta 证据；
- 本轮创建或修改的测试数据；
- 是否撤回、恢复或清理；
- 若仍为 Incomplete，列出全部已尝试通道和失败原因。

不得只写“Browser 不可用”，也不得只列 API 200。

## 4. 影响

正面影响：

- localhost 连接器拒绝不再频繁要求用户手动点击；
- M1 等阶段可以通过其他真实浏览器通道闭环；
- 页面验收质量不下降，因为真实 DOM 操作仍是硬要求；
- 工具故障与产品故障被明确区分。

代价：

- 报告需要记录通道和降级过程；
- 不同工具的 Cookie、context、截图和 Network 证据格式不同；
- 自动化脚本必须保持任务专属，不能污染仓库或其他测试数据。

## 5. 被取代的旧假设

以下旧假设被取代：

- MCP Chrome 是本地真实页面验收的唯一有效通道；
- 单一浏览器工具不可用时必须立即标记 `Incomplete`；
- 本地可回滚评分等操作必须交给用户手动完成。

保留不变的是：API、源码阅读、数据库修改和截图推测不能冒充真实页面操作。

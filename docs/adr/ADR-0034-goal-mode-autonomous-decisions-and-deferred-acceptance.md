# ADR-0034：目标模式自主决策与延迟验收

> 状态：Accepted
> 日期：2026-07-28
> 决策者：用户
> 适用范围：明确指向权威 roadmap 或有序里程碑的持续目标

本 ADR 部分取代 ADR-0031 的“未冻结产品选择一律停止”和“当前里程碑
未关闭时绝不进入任何下游工作”语义，并收紧 ADR-0033 的浏览器通道降级
分类。ADR-0031 的生产/真实用户数据、秘密、外发、付费、部署和不可逆动作
停止线继续有效；ADR-0033 的真实 DOM、用户事件和证据标准继续有效。

> **部分取代：** ADR-0037 明确切片文档接受、脏工作区语义合并和只暂停
> 受影响分支；ADR-0052 进一步以 capability clusters 取代 ADR-0034/0037
> 的所有数字化 deferred 路径预算。本 ADR 的决策梯、测试身份、平台拒绝
> 分类和诚实完成标准继续有效。

## 1. 背景与授权

用户已明确要求：

- 完成权威 roadmap 中的全部里程碑；
- 必要时修改规则，使目标模式能够连续工作；
- Anki 有成熟设计时优先采用；没有可参考设计时采用 Agent 推荐方案；
- 检查仍会重复造成阻断的规则，并允许执行 Agent 独立完成本地任务。

此前规则虽允许目标模式实施高风险切片，但仍有四类流程性阻断：

1. 低权威旧文档与当前决定不一致时，无论能否按层级消解都停止；
2. roadmap 内可逆实现细节仍被当作新的产品授权；
3. 缺少账号时无法自主建立隔离的本地验收身份；
4. 单项验收因工具/基础设施不可取得时，整个依赖图停止，其他已满足语义
   依赖的工作也不能继续。

本决定只移除这些流程性阻断，不降低安全边界和完成证据标准。

## 2. 权威冲突处理

执行 Agent 必须先判断“不一致”是哪一种：

1. **不同范围或不同阶段**：两份资料可以同时成立，不构成冲突；
2. **历史/状态滞后**：按 `AGENTS.md` 权威层级执行高权威来源；在当前切片
   允许文件内更新引用或状态，范围外只登记，不自动改写；
3. **真实冲突**：同一范围、同一行为、同一时间点提出互不相容要求。

不同权威层级的真实冲突按既有层级自动消解，不因低权威旧文本暂停。
两个已接受 ADR 若不同，先检查是否存在明确 supersession、日期和适用范围，
不得只按编号或“同级”猜测。只有同一最高有效权威内仍存在会改变行为、
数据、安全、兼容或验收的不可消解冲突时才请求用户决定。

工作区已有用户改动仍受保护。判定某文件过时不等于获得修改该文件的授权，
也不得删除历史或扩大当前切片。

## 3. 目标模式决策梯

当前切片出现计划未写死的决定时，按以下顺序处理：

1. 用户当前明确决定；
2. 已接受且适用的 ADR、模块契约和冻结的 roadmap 产品边界；
3. 当前实现和测试中经核实不是 legacy、已知 Bug 或偶然行为的稳定先例；
4. 适用时的 Anki 官方手册/官方源码行为，再映射到 LinguaCafe 的
   reading-first、sense-only、云端权威边界；
5. 没有适用先例时，选择最小、可逆、兼容且可测试的推荐方案。

现有代码和 Anki 只提供证据，不与已接受 ADR 同级。第三方论坛、模板和记忆
不能冒充 Anki 官方默认。

用户已在本持续目标中委托第 4、5 步的可逆选择。执行 Agent必须把会影响公开
接口、数据或可见行为的选择写入当前切片 plan/ADR/contract，并用正常、
拒绝和兼容测试证明；这属于用户当前委托的记录，不是 Agent 无条件自我接受
任意新产品规则。

以下决定仍不能由决策梯自动产生：

- 改变产品范围、数据权威、安全模型、认证/权限或外发边界；
- 真实用户数据删除/回填、生产 migration、不可逆领域操作；
- 任何 `migrate:fresh`、`migrate:refresh`、`migrate:reset`、`db:wipe`、
  drop 或 truncate；
- 真实 provider、秘密、付费、成本上限、部署、签名或发布；
- roadmap 外工作；
- 未被当前用户委托且会实质改变评分、生命周期、调度、数据丢失风险或
  关键无障碍承诺的不可逆产品选择。

## 4. Architecture Gate 与文件范围

目标模式仍以“已冻结切片”而不是整个里程碑作为授权单位。新发现的文件或
seam 只有同时满足以下条件才可加入：

- 直接服务当前切片已冻结责任；
- Architecture Gate 记录具体文件、责任、数据流、兼容风险和验证；
- 不引入新的产品边界或相邻功能；
- 不覆盖、回退、清理或提交工作区既有用户改动。

满足后可更新当前切片 allowlist，无需重复询问。不得用 Agent 自写的
Architecture Gate 把整个里程碑或 roadmap 变成开放范围。

## 5. 本地验收身份与测试数据

### 5.1 优先顺序

1. 用户在当前任务明确提供的本地测试账号，只有在确认位于**专用 testing
   数据库**且权限不高于当前切片所需时才复用；
2. 不满足上述条件或未提供账号时，在**专用 testing 数据库**建立一个任务专属、
   最小权限、非管理员测试身份，并让 Laravel 验收服务器也连接该 testing
   数据库；
3. 不得为了验收读取或修改既有用户密码，也不得在普通开发数据库创建后再
   通过直接数据库删除“清理”账号。

### 5.2 临时身份规则

- 标识使用 `codex-acceptance-<task-marker>@example.test`，marker 必须包含
  随机或时间成分以避免并发碰撞；
- 同一验收批次最多创建一个身份，除非隔离测试本身要求多个；
- 密码在内存中随机生成，只直接填入正常注册/登录表单；
- 密码不得进入仓库、shell 参数、命令输出、文档、截图、Network 报告、
  浏览器持久密码库或最终报告；
- 不提升管理员权限，除非切片明确验证管理员行为且通过正常产品入口授予；
- fixture 必须有唯一 marker；记录创建前后 User、ReviewCard、ReviewLog、
  token/session 和相关领域行的数量与 ID；
- 测试后关闭本轮 page/context/process，撤销本轮 token/session，并仅通过
  testing harness 回滚或经过产品生命周期入口清理；
- 清理后复核 marker、token/session 和间接写入；失败时保留证据并报告，
  不扩大删除范围。

测试身份授权不允许绕过认证、直接伪造 session、修改其他用户、清库或把
testing 授权扩大到普通开发/生产数据。

## 6. 浏览器与工具失败分类

失败必须分类后处理：

1. **页面/产品失败**：DOM、Console、Network 或数据变化显示应用错误；
   修复或如实保持失败，不得归因工具。
2. **普通通道失败**：连接器断开、进程未启动、端口错误、会话丢失等，且
   工具没有禁止替代通道；按官方插件优先和 ADR-0033 做有界诊断、清理并
   尝试下一受支持通道。
3. **显式平台安全拒绝**：系统、developer 或工具输出明确禁止同一结果的
   workaround、间接执行、原始命令或 alternate surface；该禁止高于仓库
   规则，绝不换通道规避。
4. **必须由人完成**：验证码、双重验证、系统级授权或真实账号确认。

含义不清的拒绝按更严格类别处理，不自行解释为许可。仓库 ADR 只能选择
平台允许的工具，不能覆盖系统、developer、连接器或工具安全策略。

## 7. `Acceptance Deferred — Not Complete`

当且仅当以下条件全部成立时，一个验收项可以进入唯一状态
`Acceptance Deferred — Not Complete`：

- 代码、契约、自动测试和受保护回归均通过；
- 没有已知产品缺陷或行为不确定性；
- 应用服务健康，缺失证据的原因有明确工具/基础设施/环境输出；
- 已按 §6 完成所有**平台允许**的诊断和通道尝试；
- Architecture Gate 逐项证明下游只依赖已验证契约，而不依赖缺失的页面、
  原生或外部行为；
- 按 ADR-0052 把缺失观察归入具体 capability cluster，并命名每个未验收检查。
  不使用“每条路径最多一个 deferred”的机械预算，也不因同一设备/外部能力
  还缺少第二项证据而自动终止可逆、独立可测试的实现；但每个下游 seam 都必须
  依赖已执行验证的契约，不能消费或假设缺失行为正确。

处于该状态的里程碑：

- 不是 Accept、Closed、Completed 或“已完成仅待补证据”；
- 不得更新为完成状态，不得用于最终目标完成声明；
- 只允许不触及同一未验收 seam 的下游切片继续；
- 一旦下游需要该页面/原生/外部行为，必须等待真实证据；
- 后续有可用环境时必须优先补验。

本规则部分取代 ADR-0031 的绝对阶段关闭门，但不降低最终完成标准。对 M1，
Mobile API/幂等契约是 M2 的下游依赖；既有 Web 评分页面回归是仍须补齐的
独立验收项。只要逐项审计证明 M2 不修改或依赖该 Web UI，M2 可以开始，
但 M1 和最终 M0–M18 目标仍为未完成。

## 8. 环境专属与外部动作

iOS 签名/真机、应用商店、生产部署、真实 provider、付费或其他当前环境
不可完成的动作保持开放。Architecture Gate 必须逐条证明后续本地切片与其
独立，才能继续；不得只因“看起来独立”跳过依赖。

凡是里程碑完成所必需但因环境或外部动作缺失而保持开放的验收，都统一归入
§7/ADR-0052 的 capability cluster，并使用同一
`Acceptance Deferred — Not Complete` 状态；不得通过改名为“外部开放项”、
handoff、签名待办或发布待办逃避命名检查与最终清零。

外部动作没有具体授权时只交付实现、模拟、测试和可复制 handoff，不能把
handoff 冒充外部动作完成。仍有任何环境专属必需项时，最终目标不得标记
complete。

## 9. 页面确认与写入授权

页面上的确认弹窗是产品行为，不自动授予写入权限。执行 Agent 只有在以下
条件全部满足时才可点击确认：

- 当前切片已明确授权该领域操作；
- 使用 testing 数据库中的任务专属数据；
- 正常产品入口执行，权限和 user/language 隔离保持；
- 副作用已知、有前后基线，并能由 testing harness 或产品入口收口。

AI 合并、正式评分、归档/恢复等仍分别受其领域契约约束；“测试数据”不能
把不可逆、外发或未授权操作变成可执行。

## 10. 后果与验证

正面后果：

- 低权威旧状态、可逆实现选择和单个环境证据不再让整条 roadmap 空转；
- 测试账号、浏览器和数据准备有明确的最小权限与收口方式；
- 下游工作可在契约依赖已证明时继续，同时保留诚实的未完成状态。

代价：

- Architecture Gate 必须显式写出依赖证明和 deferred evidence；
- 最终完成审计必须回查所有 `Acceptance Deferred — Not Complete`；
- 平台显式安全拒绝仍可能留下无法由仓库规则消除的人工/环境步骤。

验证：

- `node tests/js/GoalModeAutonomyDocsGuard.test.mjs`
- `node tests/js/GoalRoadmapExecutionAuthorizationDocsGuard.test.mjs`
- `node tests/js/GoalStagePreauthorizationDocsGuard.test.mjs`
- `git diff --check`
- 最多三轮新鲜上下文对抗审查
